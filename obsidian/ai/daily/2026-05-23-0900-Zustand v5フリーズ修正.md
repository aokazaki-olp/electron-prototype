# Zustand v5 フリーズ修正・テーブル描画改善

## 作業概要

electron-prototype（Salesforce Explorer）で `npm run dev` 時にUI操作でJSメインスレッドがフリーズする問題を調査・修正した。

## 根本原因

Zustand v5 は内部で `useSyncExternalStore` を使用しており、セレクタなしで `useAppStore()` を呼ぶと、`appendLog` など無関係な store 更新でも全コンポーネントが同期的に再レンダーされる。ログが流れるたびにこれが起き、イベントループが占有され IPC レスポンスのマイクロタスクが処理されなくなりフリーズした。

## 修正内容

### フリーズ修正
- App / MainPage / SObjectBrowser / SoqlEditor に `useShallow` セレクタを追加
- SObjectBrowser・SoqlEditor を `React.memo` でラップ
- `setSoql + incrementRunTrigger` を `setSoqlAndRun` アトミックアクションに統合
- `CM_EXTENSIONS`・`CM_BASIC_SETUP` をモジュールスコープに固定（CodeMirror の毎回再構成を防止）
- `runQueryRef + lastRunTriggerRef` パターンで runTrigger の二重実行を防止

### バグ修正（ダブルクリック時の誤った SOQL）
ブラウザは `dblclick` より前に `click` を2回発火する。`onClick` で `selectedObject` が更新されるため、`onDoubleClick` 時点では `selectedObject === name` が常に true になり、古い `describe`（前オブジェクトのフィールド）で SOQL が生成されていた。

修正: `desc && selectedObject === name` → `desc && desc.name === name`

### ResultTable 描画修正
`<tr style="position:absolute">` を `<tbody>` 内で使う方式は HTML テーブルレイアウト算に参加しないためヘッダーと列幅がずれる。TanStack Virtual 推奨のパディング行方式（上下に高さ調整用 `<tr>` を置く）に変更。

### SObjectBrowser 仮想スクロール化
sObject 一覧を `useVirtualizer` で仮想スクロール化し、大量オブジェクト時の描画を軽量化。
