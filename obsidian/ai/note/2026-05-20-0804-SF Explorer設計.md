# Salesforce Explorer 設計メモ

A5:SQL Mk-2 の Salesforce版プロトタイプ。壁打ちで確定した設計の記録。

## 基本情報

| 項目 | 内容 |
|---|---|
| アプリ名 | Salesforce Explorer |
| プラットフォーム | Windows 専用 |
| スタック | Electron 32 + React 18 + TypeScript + TailwindCSS + electron-vite |
| 参考 | A5:SQL Mk-2（sObjectブラウザ・SOQLエディタ・オブジェクト定義書生成） |

## ゴール（Phase 1–2）

> [!abstract] スコープ
> Phase 3（オブジェクト関連図・AIアシスタント）は対象外。

**Phase 1**
- 設定画面 + OAuth PKCE認証
- sObjectブラウザ（一覧 → フィールド詳細）
- SOQLエディタ + 結果テーブル

**Phase 2**
- CSV / Excel エクスポート
- オブジェクト定義書生成（Excel）

## 認証設計

> [!info] PKCE必須化
> Salesforce は 2026年5月11日に PKCE + Refresh Token Rotation を全アプリに必須化。この設計は対応済み。

- **フロー**: OAuth 2.0 Web Server Flow + PKCE (S256)
- **state パラメータ**: 必須（CSRF対策 / RFC 6749 §10.12）
- **コールバック**: `http://localhost:8787/callback`（固定ポート）
- **refresh_token**: `safeStorage` (DPAPI) で暗号化 → `electron-store` に保存
- **access_token**: main プロセスメモリのみ（永続化なし）
- **起動時**: refresh_token があれば自動リフレッシュ、なければ設定画面へ

## 接続プロファイル

```typescript
interface SfConnectionProfile {
  id: string;
  name: string;
  loginUrl: string;       // https://login.salesforce.com 等
  clientId: string;
  mode: 'readonly' | 'readwrite';
  writeSessionTimeoutMin: number; // 5 / 15 / 30 / 60 / 0=毎回, default: 15
}
```

- 複数プロファイル管理（本番 / sandbox / 開発 org 切り替え）
- `readonly`: DML 系 IPC メソッドを完全ブロック（UI + IPC の二重防衛）
- `readwrite`: DML 実行時に警告 + OAuth 再認証 → タイムアウト内は再認証不要

### 書き込みセッション

```
DML実行
  ├─ readonly     → IPC即時拒否
  └─ readwrite
       ├─ セッション有効 → 実行
       └─ セッション無効（未認証 or タイムアウト）
            → 警告ダイアログ + OAuth再フロー
            → 成功 → writeSessionMap.set(profileId, Date.now())
```

> [!warning] 設計上の注意
> readonly / readwrite の制御は **IPC メソッド単位**で行う。SOQL 文字列のパースによる DML 検出は使わない（Salesforce の `/query` は SELECT 専用のため）。

`writeSessionMap` は main メモリのみ。再起動でリセット。

## DML 監査ログ

- `electron-log` の audit 専用トランスポートで別ファイルに記録
- 記録内容: `timestamp` / `profileName` / `operationType` / `recordsAffected`

## describe キャッシュ

- main プロセスのメモリキャッシュ（同セッション内）
- 再接続・プロファイル切り替え時にクリア

## CSV 出力設計

| 設定 | 内容 |
|---|---|
| ライブラリ | `csv-stringify`（RFC 4180 準拠） |
| BOM | 保存時にユーザー選択（デフォルト: あり） |
| 改行コード | CRLF / LF を保存時に選択（デフォルト: CRLF） |

## クエリ結果件数設定

A5M2 のデフォルト 10,000 件 / 全件取得に倣った設計。

- 設定画面で変更可能: `500 / 1,000 / 2,000 / 5,000 / 10,000 / 無制限`
- デフォルト: **2,000 件**（Salesforce API の 1 ページ分）
- 実行時に「件数制限を無効にして全件取得」チェックで一時解除（警告付き）
- `nextRecordsUrl` を透過的に辿って全件取得

## ログビューアー（内蔵）

- `electron-log` からリアルタイムストリーミング（IPC push）
- アプリログ + DML 監査ログを統合表示
- レベルフィルタ（DEBUG / INFO / WARN / ERROR）
- テキスト検索 / 自動スクロール ON・OFF
- `electron-log` の hook で token 類を自動マスク

## 採用しなかった選択肢

| 選択肢 | 理由 |
|---|---|
| 動的ポート | Connected App の URI 設定が複雑になるため。固定 8787 を維持 |
| SOQL 文字列パースによる DML 検出 | `/query` は SELECT 専用。IPC メソッド単位制御に変更 |
| 自前 CSV 実装 | RFC 4180 の罠（NaN・引用符）を避けるため csv-stringify を採用 |
| Username-Password Flow | Salesforce が廃止方向のため不採用 |
| JWT Bearer Flow | サーバー間連携向け。ユーザー操作型の本アプリには不適 |
