# UI 違和感ポイント一覧（初回レビュー）

`apps/explorer/src/renderer/` 配下を一通り読んで挙げた、現在の UI で気になる箇所のフラットな棚卸し。  
**この一覧自体は table stakes（使いやすさの底上げ）レベルの話**で、ここを全部直しても類似アプリ（Workbench / Inspector）の改良版にしかならない。本命の差別化軸は [[2026-05-24-0928-UX差別化軸3案]] で別途整理した。

> [!warning] 優先順位の前提
> このリストの S/M/L 優先度は **差別化軸が未決の今時点**での暫定。差別化軸が A+C などに決まると、たとえば「**結果テーブルの skeleton 表現**」は「**Claude が結果を解釈中の表現**」も兼ねる必要が出てきて設計が変わる。**差別化軸を決めてから polish を確定する**順序を守る ([[feedback_ux_differentiation_first]])。

---

## A. 致命的に効きが弱い箇所

### A1. ペインのサイズが全部固定（S 優先）

- 関連: [apps/explorer/src/renderer/pages/MainPage.tsx:108](../../../apps/explorer/src/renderer/pages/MainPage.tsx#L108) `w-64 flex-shrink-0`、[MainPage.tsx:115](../../../apps/explorer/src/renderer/pages/MainPage.tsx#L115) `height: 40%`
- 現状: 左ペイン 256px 固定、SOQL エディタ高さ 40% 固定。ユーザーがリサイズできない
- 問題:
  - 長い SOQL を書いている時は結果を狭くしたい、結果を見ている時はエディタを潰したい — どちらも不可能
  - 日本語ラベルの sObject 一覧が 256px で truncate されて判別困難なケースがある
- 提案:
  - 3 ペインスプリッタ（左 / 中央上 / 中央下）。`react-resizable-panels` か自前実装
  - サイズは electron-store に永続化（[[CODING_RULES]] §7.3 遵守、localStorage 不可）
- なぜ S: dev tool として「自分の画面構成を作れない」のは最も基礎的な不満。差別化軸に依存せず常に正解

### A2. 「どの org に繋がっているか」のシグナルが弱い（S 優先）

- 関連: [MainPage.tsx:65-79](../../../apps/explorer/src/renderer/pages/MainPage.tsx#L65-L79)
- 現状: ヘッダーに `Salesforce Explorer | プロファイル名 | 読み取り専用バッジ` のみ
- 問題:
  - **instanceUrl / 環境種別（prod/sandbox/scratch）/ Salesforce ユーザー名** がどこにも見えない
  - 複数 org を切替えるバッチ開発者にとって**誤接続事故**が最も怖いシナリオ
  - readwrite モード時にバッジ色は変わるが、本番 org への書込誤操作を阻止するには弱い
- 提案:
  - 接続中チップに `prod` / `sandbox` / `scratch` ラベル（loginUrl から判別）
  - Hover で SF username + instanceUrl 表示
  - **readwrite モード時はヘッダー帯ごとオレンジ**（背景色を全幅で変える）
- なぜ S: 事故防止系は最優先。誤接続で本番に書込してしまったらアプリの信頼が全壊する

### A3. タブの自動命名が文脈ゼロ（S 優先）

- 関連: [store.ts:122](../../../apps/explorer/src/renderer/store.ts#L122)（`クエリ N` 採番）、[SObjectBrowser.tsx:67-68](../../../apps/explorer/src/renderer/components/SObjectBrowser.tsx#L67-L68)（dblclick で SOQL セット）
- 現状: sObject をダブルクリックで SOQL が入っても、タブ名は `クエリ N` のまま
- 問題: 5 つ並ぶと「どのタブが何だっけ」を毎回開いて確認する羽目になる。手動 rename 率が高そう
- 提案:
  - ダブルクリック起点なら `SELECT Account` のような名前を自動採用
  - 手動入力タブのみ `クエリ N` フォールバック
  - 既に rename 済みのタブは上書きしない
- なぜ S: 改修が小さく、効果が日常的に体感される

### A4. 空状態（Empty State）が薄い（S 優先）

- 関連: [ResultTable.tsx:142](../../../apps/explorer/src/renderer/components/ResultTable.tsx#L142)
- 現状: 「SOQL を実行すると結果が表示されます」のみ
- 問題: [[user_salesforce_new]] にある通り SF 新規ユーザーには白紙からの SOQL 起動が辛い
- 提案:
  - 起動直後/空タブには **スニペットチップ**を並べる
    - `SELECT Id, Name FROM Account LIMIT 10`
    - `SELECT COUNT(Id) FROM Lead WHERE CreatedDate = TODAY`
    - `SELECT Id, Name, Owner.Name FROM Opportunity WHERE IsClosed = false LIMIT 50`
  - クリックで挿入。最初の数回でユーザーが SOQL の構文感を掴める
  - SF 予約語ヘルプを下部に小さく
- なぜ S: companion ツールとしての**温度**が一番低い箇所。直すと印象が変わる

### A5. エラーが全部バラバラのインライン alert（S 優先）

- 関連:
  - disconnect 失敗: [MainPage.tsx:98](../../../apps/explorer/src/renderer/pages/MainPage.tsx#L98)
  - 設定保存失敗: [SettingsPage.tsx:149](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx#L149)
  - 認証失敗: [SettingsPage.tsx:287](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx#L287)
  - エクスポート失敗: [ResultTable.tsx:185](../../../apps/explorer/src/renderer/components/ResultTable.tsx#L185)
  - SOQL 失敗: [SoqlEditor.tsx:262](../../../apps/explorer/src/renderer/components/SoqlEditor.tsx#L262)
- 現状: 5 箇所以上で個別のインライン `role="alert"`
- 問題:
  - **どこにエラーが出るか毎回探す**羽目になる
  - 連続エラー時に下のエラーが上のエラーで隠れる
  - 履歴に残らない（消すと消える）
- 提案:
  - 右下トースト（`sonner` あるいは自前で 80 行程度）に統一
  - 詳細は LogViewer に飛ぶリンク
  - 重大度別（error/warn/info）のアイコン
- なぜ S: 一貫性は使いやすさ全体に効く。ライブラリ追加するなら今のうち

## B. dev tool として古くさい箇所

### B6. CodeMirror の SOQL サポートが `sql()` だけ（M 優先・差別化軸次第で S）

- 関連: [SoqlEditor.tsx:10](../../../apps/explorer/src/renderer/components/SoqlEditor.tsx#L10) `const CM_EXTENSIONS = [sql()]`
- 現状: 一般 SQL の syntax highlight のみ。SF 固有関数の補完なし、選択中 sObject のフィールド補完なし
- 問題: 「クエリ検証 companion」を名乗るなら、選択中 sObject の `describe.fields` を引いた**フィールド補完は本丸機能**であって周辺機能ではない
- 提案:
  - `@codemirror/autocomplete` 利用
  - 選択中 sObject の describe をソースに、`SELECT <カーソル>` 位置でフィールド候補
  - `FROM` 直後で sObject 名候補
  - SF 関数（`COUNT`, `COUNT_DISTINCT`, `CALENDAR_YEAR`, `TYPEOF`, `IN`, `INCLUDES` 等）の予約語補完
  - フィールド hover で `type` / `label` をポップオーバー
- なぜ差別化軸次第:
  - 差別化軸 A（Claude 副操縦士）を採るなら、補完候補に **「Claude に意図を確認」** が混ざる設計になりうる
  - 軸 C（ローカルミラー）を採るなら、補完ソースがローカル SQLite から引かれる
  - 軸決定後に設計を確定する方が無駄がない

### B7. コマンドパレット / グローバルショートカットが乏しい（M 優先）

- 関連: [SoqlEditor.tsx:124-135](../../../apps/explorer/src/renderer/components/SoqlEditor.tsx#L124-L135)（Ctrl+Enter / Ctrl+S のみ）
- 現状: 実行と保存だけ。タブ切替・コマンドパレットなし
- 提案:
  - `Ctrl+T` 新規タブ / `Ctrl+W` タブ閉じる
  - `Ctrl+Tab` で次タブ
  - `Ctrl+P` で sObject クイック検索（VS Code 風）
  - `Ctrl+K` でコマンドパレット（モダン dev tool の最低ライン）
- 注: 軸 A 採用なら `Ctrl+K` は「Claude に依頼」に統合

### B8. dark mode 不在（M 優先）

- 関連: [index.css](../../../apps/explorer/src/renderer/index.css) は Tailwind base のみ
- 現状: LogViewer だけが slate-900。他は white/slate-50 のライト
- 問題: ヘビーユーザーが何時間も使う前提で light only は時代的に厳しい
- 提案:
  - CSS 変数化 + Tailwind `dark:` クラス
  - 設定からトグル、OS 追従オプション
  - LogViewer はもう dark なので、揃える方向に
- 補足: companion 用途で長時間張り付くため、目への負担は地味に効く

### B9. ResultTable の列幅が固定 truncate（M 優先）

- 関連: [ResultTable.tsx:229](../../../apps/explorer/src/renderer/components/ResultTable.tsx#L229) `max-w-xs truncate`
- 現状: 全列同サイズで切り詰め
- 問題: Id 18 桁と Description 500 文字が同じ幅。表として情報密度が悪い
- 提案:
  - `@tanstack/react-table` の column sizing で drag-resize
  - 列幅・並び順を sObject 別 + フィールド別に永続化
  - auto-fit ボタン（中身に合わせて自動調整）

### B10. CSV だけ詳細ダイアログ、Excel は即発火（M 優先）

- 関連: [ResultTable.tsx:166-181](../../../apps/explorer/src/renderer/components/ResultTable.tsx#L166-L181)
- 現状: CSV はモーダルで BOM / 改行を選ぶ、Excel は即保存ダイアログ
- 問題: 同じ「保存」操作で挙動が非対称、ユーザーが迷う
- 提案:
  - ボタンを 1 つの dropdown に統合: `CSV (BOM 付き)` / `CSV…（詳細設定）` / `Excel`
  - デフォルトはワンクリック保存、詳細設定はオプション

## C. 機能と設定の不一致

### C11. readwrite モードが設定にあるのに UI で使えない（S 優先・判断必要）

- 関連: [SettingsPage.tsx:213](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx#L213)（モード select）、契約に [csp-security.spec.ts:75](../../../tests/e2e/specs/csp-security.spec.ts#L75) で `createRecord/updateRecord/deleteRecord` 確認済み
- 現状: 設定で readwrite を選べるが、レンダラーに書込呼び出し口がない
- 問題: 「オプション選べるのに何も起きない」は混乱の元
- 判断必要な選択肢:
  - (a) readonly 固定にして UI から readwrite 設定を一旦隠す（プロトタイプ枠なら合理）
  - (b) 最低限の書込 UI（編集ダイアログ）を作る
  - (c) 「将来機能。現状は readonly として動作」と明記
- 推奨: プロトタイプ枠を維持するなら (a)。本気で書込を入れるなら差別化軸 B（バッチ workflow）と一緒に設計
- なぜ S: 整合性は基礎品質。「動かないボタン」より「ない」が誠実

### C12. 「無制限」「2000 件」などのデフォルト値の根拠説明がない（M 優先）

- 関連: [SettingsPage.tsx:309](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx#L309)
- 現状: 500 / 1000 / 2000 / 5000 / 10000 / 無制限 の数字だけ
- 問題: SF 新規ユーザーは「2000 件で何が起きる？50000 件取れるの？無制限ってメモリ大丈夫？」を知らない
- 提案: ヘルプアイコン + popover で「SF REST API は最大 2000 件/ページ。無制限はページング全走査。10000 件超えは数秒待つ」と短く

### C13. 「ファイル保存」と「クエリ保存」の言葉の衝突（M 優先）

- 関連: [SoqlEditor.tsx:241](../../../apps/explorer/src/renderer/components/SoqlEditor.tsx#L241)
- 現状: ボタンが単に `保存`
- 問題: SF 文脈で「保存」はレコード保存を想起させる
- 提案: `.soql に保存` / `.soql を開く` と明示。アイコン（FloppyDisk / Folder）も意味を強化

## D. 細かいが気になる

### D14. 設定モーダルにフォーカストラップなし（L 優先）

- 関連: [App.tsx:118-140](../../../apps/explorer/src/renderer/App.tsx#L118-L140)
- 現状: Tab キーで背後のエディタにフォーカスが抜ける
- 提案: フォーカストラップ実装（`focus-trap-react` か手書き 30 行）
- a11y 的に惜しい

### D15. 接続中の進捗が「接続中...」だけ（M 優先・体験影響大）

- 関連: [SettingsPage.tsx:278](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx#L278)
- 現状: ボタンの文字だけが変わる
- 問題: OAuth でブラウザが開く間、ユーザーは「何が起きてるか分からない」
- 提案: ステップ表示
  1. 「ブラウザを開きます」
  2. 「Salesforce でログイン中... ブラウザに戻ってください」
  3. 「コールバック受信中...」
  4. 「接続完了」
- これは [[feedback_ui_goal_is_beauty]] の「待ち時間が静止しない」原則と直結

### D16. タブの ✕ ボタンが hover でしか出ない（L 優先）

- 関連: [SoqlEditor.tsx:181](../../../apps/explorer/src/renderer/components/SoqlEditor.tsx#L181) `opacity-0 group-hover:opacity-100`
- 現状: マウス hover でないと閉じるボタンが見えない
- 問題: 発見性が低い、touch / 狭幅マウスユーザーが触れない、e2e の `dispatchEvent` ベースでは hover 不要だが**実ユーザーが触る経路と乖離**
- 提案: アクティブタブだけ常時表示、非アクティブは hover で表示
- 関連: [[2026-05-24-XXXX-e2e観察]]（e2e の hover 検査ギャップとセット）

### D17. 削除確認モーダルに対象名が出ない（M 優先）

- 関連: [SettingsPage.tsx:333](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx#L333)
- 現状: 「この操作は取り消せません。続行しますか？」のみ
- 問題: **どのプロファイル名を消すか文中に出ていない**
- 提案: 「**プロファイル "本番 org" を削除します。この操作は取り消せません。**」
- 誤削除事故防止

### D18. LogViewer 1000 件カット（M 優先）

- 関連: [store.ts:112](../../../apps/explorer/src/renderer/store.ts#L112) `logs.slice(-999)`
- 現状: 直近 1000 件で打ち切り
- 問題: バッチ開発のデバッグ中はもっと欲しい場面がある
- 提案:
  - 設定で可変（1000 / 5000 / 10000 / 無制限）
  - 「ファイルに保存」ボタンで現在のログを `.log` にダンプ
  - 無制限時はメモリ警告

## 優先度のまとめ

| 優先度 | 項目 |
|---|---|
| **S（差別化軸に依存せず先行可能）** | A1, A2, A3, A4, A5, C11 |
| **M（dev tool の体裁を整える層）** | B7, B8, B9, B10, C12, C13, D15, D17, D18 |
| **L（後回しでも可）** | D14, D16 |
| **S だが差別化軸決定後に設計確定すべき** | B6（補完エンジン） |

S 層だけ先に着手して構わない。M 以下は差別化軸（[[2026-05-24-0928-UX差別化軸3案]]）が決まってから着手する方が、二度手間が減る。

## 派生する観点（このリストには含めなかった）

これらは「**この一覧（table stakes）の各項目をどう実装するか**」を決める上位レイヤー。リスト自体には混ぜず、別 note で扱う。
