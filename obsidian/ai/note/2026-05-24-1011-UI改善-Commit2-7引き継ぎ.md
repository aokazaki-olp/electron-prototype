### Commit 2: テーブルアニメ + A5 toast 統一

**要件**:
- REST/Bulk 共通の **skeleton + dim + 経過秒数カウンタ**（main 触らない、レンダラー側のみ）。ユーザー指示通り (a) 案。
- Bulk 実行時は数十秒〜数分かかるので、`Bulk実行中... 12秒経過` のような表示が要る。`SoqlEditor.tsx` の executionMode と queryLoading 駆動。
- 既存 5 箇所以上のインライン `role="alert"` を **右下トーストに統一**:
  - [MainPage.tsx](../../../apps/explorer/src/renderer/pages/MainPage.tsx) disconnectError
  - [SettingsPage.tsx](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx) saveError / authErrors
  - [ResultTable.tsx](../../../apps/explorer/src/renderer/components/ResultTable.tsx) exportError
  - [SoqlEditor.tsx](../../../apps/explorer/src/renderer/components/SoqlEditor.tsx) error
  - [LogViewer.tsx](../../../apps/explorer/src/renderer/components/LogViewer.tsx) exportError (Commit 1 で追加)
  - [SObjectBrowser.tsx](../../../apps/explorer/src/renderer/components/SObjectBrowser.tsx) loadError / exportError

**ライブラリ**: 自前で 80 行のトースト Provider（[[feedback_solo_no_contributing_md]] のプロトタイプ精神に従って依存最小化）。`sonner` でも可だが、現状の dependency 数を抑えたい。

**実装ポイント**:
- `ResultTable.tsx` で `result === null && queryLoading` 時は **dim + skeleton 3〜5 行**、`result != null && queryLoading` 時は **既存 result を opacity-40 + skeleton overlay**
- skeleton は CSS `animate-pulse` で十分（依存追加なし）
- 経過秒数は `useEffect` + `setInterval(1000)` で local state、`queryLoading` false で clear
- トースト: `ToastContext` provider を `App.tsx` で wrap、`useToast()` hook で呼ぶ。`{ message, level, durationMs?, action? }` を queue する fixed bottom-right コンポーネント

**e2e への影響**:
- 既存の `getByRole('alert')` ベースの assertion は壊れる可能性大。トースト自体に `role="alert"` を付ければ通る
- [error-handling.spec.ts](../../../tests/e2e/specs/error-handling.spec.ts), [csv-export.spec.ts](../../../tests/e2e/specs/csv-export.spec.ts) が影響範囲
- skeleton の存在を assert するテストを 1 本追加すると polish の regress 検出になる

**注意**:
- queryLoading は store.ts に既に居る（SoqlEditor が set してる）。Commit 2 では ResultTable から store の queryLoading を subscribe する形が一番すっきり
- SoqlEditor の `executionMode` は SoqlEditor 内 local state。ResultTable に渡すなら MainPage 経由で props bubble up が必要 → あるいは ResultTable は executionMode を知らず「Bulk か否かを問わず queryLoading なら skeleton + 経過秒数」だけ表現する単純化が現実的

### Commit 3: A1 resize panels

**要件**:
- 左ペイン (SObjectBrowser 256px 固定) と 中央上下 (SoqlEditor 40% 固定 + ResultTable/LogViewer 60%) を**ユーザーがドラッグでリサイズ可能に**
- サイズは electron-store に永続化（CODING_RULES §7.3 遵守、localStorage NG）

**ライブラリ**: `react-resizable-panels` (事実上の標準、軽量、Tailwind と相性良)

```bash
npm i -w @app/explorer react-resizable-panels
```

**実装ポイント**:
- [MainPage.tsx](../../../apps/explorer/src/renderer/pages/MainPage.tsx) の `<div className="flex flex-1 overflow-hidden">` 部分を `<PanelGroup direction="horizontal">` で置換
- 中央ペインの上下も `<PanelGroup direction="vertical">` でネスト
- `onLayout` callback でサイズを取得 → debounce 300ms → store → IPC で main の electron-store へ
- 永続化用に **新 IPC `PANE_SIZES` (load/save)** が必要、または `AppSettings` に `paneSizes` を入れる（後者の方が IPC を増やさず良い）
- 既定値: 左 18%、SOQL 上 40%、結果下 60%

**e2e への影響**:
- MainPagePOM の locator のうち、特定の class (`.w-64` 等) を使っていないので大半は無事。要確認

### Commit 4: B10 CSV/Excel dropdown + B9 列幅 resize

**B10 CSV/Excel dropdown**:
- 現状 [ResultTable.tsx:166-181](../../../apps/explorer/src/renderer/components/ResultTable.tsx#L166-L181) で CSV は詳細ダイアログ、Excel は即発火。非対称
- ボタン 2 つを 1 つの dropdown に統合: `エクスポート ▾` → `CSV (BOM+CRLF)` / `CSV…（詳細）` / `Excel`
- dropdown は自前（30 行程度、headlessui 不要）

**B9 列幅 resize**:
- TanStack Table の `enableColumnResizing: true` + ヘッダー右端 drag handle
- 列幅は `useState` で持ち、debounce 500ms で **sObject 別 + 列名別**に electron-store に永続化
- `columnSizing` state を `useReactTable` に渡す
- 列ヘッダー th の右端に `<div className="resize-handle">` を絶対配置、`onMouseDown` で drag 開始
- 公式 doc: <https://tanstack.com/table/v8/docs/guide/column-sizing>

**e2e への影響**:
- CSV ダイアログの開閉テスト ([csv-export.spec.ts](../../../tests/e2e/specs/csv-export.spec.ts)) の起点 button label が変わる
- 列幅永続化のテストは追加してもよい（regression 価値高）

### Commit 5: B7 グローバルショートカット

**要件**:
- `Ctrl+T` 新規タブ / `Ctrl+W` タブ閉じる / `Ctrl+Tab` 次タブ / `Ctrl+Shift+Tab` 前タブ / `Ctrl+P` sObject クイック検索 / `Ctrl+K` コマンドパレット
- IME composition (`isComposing`) と input/textarea フォーカス時は基本スキップ

**ライブラリ**: 自前。`useGlobalKeybindings` hook を新設して `App.tsx` の trunk で 1 回だけ install。`mousetrap` 等は不要。

**実装ポイント**:
- key map を 1 箇所に集約: `{ 'Ctrl+T': addTab, 'Ctrl+W': closeActiveTab, ... }`
- 入力フィールド (input / textarea / contenteditable) 内では実行しない（CodeMirror も contenteditable）
- ヘルプ overlay (`Ctrl+/`) で keymap を一覧表示するのもアリ

**注意**:
- e2e の `pressKey` ヘルパーは document.dispatchEvent ベースなので普通に動く
- Ctrl+P は sObject クイック検索 → 専用の Command palette UI を作る必要があるが、これは Commit 5 のスコープに含めるか別 commit か要判断。**最低限 Ctrl+T / Ctrl+W / Ctrl+Tab だけ実装してパレットは TODO** が現実的

### Commit 6: B6 SOQL 補完

**要件**:
- CodeMirror v6 の `@codemirror/autocomplete` を有効化
- 補完ソース:
  - `SELECT <cursor>` 位置 → 選択中 sObject の `describe.fields` から列補完
  - `FROM <cursor>` 位置 → sObject 一覧から名前補完
  - SF 予約語 (`SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT, OFFSET, FOR UPDATE, FOR VIEW, FOR REFERENCE, TYPEOF, USING SCOPE`)
  - SF 関数 (`COUNT, COUNT_DISTINCT, MIN, MAX, SUM, AVG, CALENDAR_YEAR, CALENDAR_MONTH, FORMAT, INCLUDES, EXCLUDES, IN`)
  - 日付リテラル (`TODAY, YESTERDAY, TOMORROW, THIS_WEEK, LAST_N_DAYS:N, ...`)

**ライブラリ**: `@codemirror/autocomplete` (CodeMirror v6 公式)

```bash
npm i -D @codemirror/autocomplete
```

**実装ポイント**:
- 補完ソースは `CompletionSource` 関数。`CompletionContext.matchBefore(/\w*/)` でカーソル前の token を取って候補を返す
- sObject describe は SObjectBrowser の `describe` state に居る。これを取り出す経路が必要 → store に `selectedObjectDescribe` を昇格させるか、SoqlEditor が自分で `window.sfx.describeObject` を呼ぶか
- 後者だと describe を二度呼ぶことになる → store 昇格が筋
- 補完候補の絞り込みは CodeMirror が自動でやる
- CodeMirror v6 公式 doc: <https://codemirror.net/docs/ref/#autocomplete>

**設計判断**:
- 簡易版 vs 完全版で分けられる。簡易版 = 予約語 + sObject 名のみ、完全版 = フィールド補完まで。**簡易版を Commit 6、フィールド補完を Commit 6.5 として分ける**判断もアリ
- 差別化軸が決まったら（[[2026-05-24-0928-UX差別化軸3案]] の A 案採用時）「Claude に意図確認」を補完候補に混ぜる設計に発展しうるが、まずは基礎補完で

### Commit 7: B8 dark mode

**要件**:
- `tailwind.config.ts` の `darkMode: 'class'` 化
- 全画面の `bg-white`, `bg-slate-50/100/200`, `text-slate-*` 等を `dark:` バリアント付きで書き直し
- 設定からトグル可能 (`AppSettings.theme: 'light' | 'dark' | 'system'`)
- OS 追従 (`system`) は `prefers-color-scheme` watch
- `document.documentElement.classList.toggle('dark', isDark)` で適用

**実装範囲**:
- [tailwind.config.ts](../../../apps/explorer/tailwind.config.ts): `darkMode: 'class'` 追加
- [AppSettings](../../../packages/ipc-contract/src/contract.ts): `theme` 追加 (`'light' | 'dark' | 'system'`)
- [main-core/settings.ts](../../../packages/main-core/src/settings.ts): DEFAULT_SETTINGS に追加、guards に追加
- [App.tsx](../../../apps/explorer/src/renderer/App.tsx): theme effect で classList 操作
- [SettingsPage.tsx](../../../apps/explorer/src/renderer/pages/SettingsPage.tsx): theme select 追加
- 各 component の Tailwind クラスに `dark:` バリアント追加
  - MainPage 全体
  - SettingsPage 全体
  - ResultTable
  - SObjectBrowser
  - SoqlEditor (CodeMirror の theme も切替: `theme="light"` → 条件付き)
  - LogViewer はすでに dark なのでそのまま、light モードでは逆にライトに

**注意**:
- CodeMirror の theme prop は `'light' | 'dark' | Extension` を受ける。`useAppStore` の theme を引いて条件分岐
- e2e への影響は小さい（class 名が増えるだけで構造は変わらない）

## 各 commit の作業フロー (推奨)

各 commit ごとに必ず通す:

1. 実装
2. `npm run typecheck` で型 OK
3. `npm test` で 286+ 件 pass
4. ファイル個別指定で `git add`（`-A` は使わない、`.claude/settings.json` を巻き込まないため）
5. HEREDOC で commit message を書いて `git commit`
6. `git status` で残差確認
7. 次の commit へ

e2e (`npm run test:e2e`) は重い（5〜10 分）。Commit 7 完了後にまとめて 1 回走らせて regression を見るのが現実的。
